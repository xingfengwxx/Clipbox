## 1. 背景与目标

Clipbox 当前以单一共享数据空间运行：已配对设备共享剪贴记录，服务端提供增量同步、一次性分享与设备配对；工具箱包含 JSON、Base64、URL、时间戳和正则五项本地工具。现有路线图已把设备管理与令牌撤销、分享撤销、工具箱扩展列为 v1.2 候选，见[功能需求文档 §3.3](功能需求文档.md#33-版本路线)。

v1.2.0 的主要变化是支持同一服务端承载多个相互隔离的共享空间。一个空间由相互配对的设备组成；该空间内不同的一次性配对码都把新设备加入同一空间。空间内设备共享同步数据、设备管理和分享管理。

开始 v1.2.0 时 M6 官网验收和 M7 发布收尾尚未关闭。按已确认的执行顺序，v1.2.0 与 v1.1.0 收尾分开推进；未完成的 M6/M7 状态和发布门槛仍保持有效，不因本路线图自动关闭。

## 2. 版本范围与优先级

### P0：稳定设备身份与多空间隔离

- App 启动时取得平台生命周期内稳定的设备标识；设备标识用于识别设备，不作为认证凭据。认证继续依赖独立的随机设备令牌。
- 首次使用时提供“创建新空间”和“输入配对码加入空间”两种明确操作。创建空间时原子创建空间与首台设备；加入时，服务端根据配对码签发者所属空间添加设备。
- 同一空间的任意成员设备可以生成不同的一次性配对码；每个码都只能被消费一次，并把新设备加入该码签发者所在空间。
- 空间 ID 由服务端管理。客户端请求剪贴记录、同步、设备或分享数据时不传入可选择的空间 ID；服务端从已认证设备解析其空间，所有读取和写入都必须受该空间约束。
- WebSocket 事件仅广播给同一空间的成员。`serverSeq`、`sync_floor` 与同步缺口判断按空间隔离，保证客户端仍只应用连续事件；剪贴记录保留策略也按空间分别执行，避免一个空间的写入影响另一空间的数据保留。
- 新设备标识按已冻结的实现选择：Android 使用 `ANDROID_ID`，iOS 使用 `identifierForVendor`，Desktop 使用本地持久化随机 UUID；不上传原始硬件标识。三端均检查卸载重装后的实际表现；系统或本地数据条件导致标识变化时视为新设备并重新配对。
- 设备标识不恢复认证令牌。重装后若令牌丢失，用户仍须通过同空间其他设备生成的配对码重新配对；仅凭设备标识不得恢复访问权限。

### P1：空间内设备与分享管理

- 设备管理展示当前空间成员设备的名称、创建时间、最近活动时间及当前设备标记。空间成员可以撤销其他设备的访问令牌；服务端立即拒绝其后续 REST 请求并关闭其 WebSocket 连接。
- 撤销最后一台设备时，通过二次确认删除该空间在线数据，包括设备、剪贴记录、分享、配对码及空间同步状态。在线删除后不再有设备可访问该空间。
- 分享管理展示当前空间仍有效的分享及可区分它们所需的摘要信息（例如正文预览、创建时间、有效期和一次性状态），支持主动撤销。分享列表使用独立的分享记录 ID，不暴露或重建仅以哈希保存的分享令牌；撤销后原链接不可访问。
- 删除最后设备或撤销分享不更改现有整库备份周期。已删除空间可能暂时保留在最近 7 份/7 天备份中；从删除前备份恢复服务端数据时，可能恢复该空间数据。该限制必须在确认界面或帮助说明中明确。

### P2：工具箱扩展

- 增加 JWT 解码、SHA-256 摘要、UUID/ULID 生成。
- JWT 工具只解析并展示头部和载荷，不验证签名、不判断令牌有效性；界面明确显示此限制。
- 三项工具均离线运行，不写入剪贴历史、不上传输入输出、不记录输入输出日志。

### 本版不包含

- 用户名密码注册、云端身份登录、账号找回或同一客户端同时管理多个空间。
- 片段收藏、Android/iOS 后台通知、桌面托盘、全局快捷键；这些保持为既有 v1.1.x 候选。
- 端到端加密，仍按 v2.0 单独评估。
- 本版不改变分享页公开只读、安全头和一次性消费的既有行为。

## 3. 冻结接口与数据迁移契约

以下行为、字段与隔离约束已经在需求、API、架构和 ADR 中冻结：

- `POST /api/v1/spaces` 原子创建空间与首台设备，按 IP 限流；`POST /api/v1/bootstrap` 只为旧客户端保留空库初始化兼容。
- 配对码绑定签发设备所属空间。`installationId` 是非认证元数据；同空间的有效重复配对复用设备 ID、更新名称并轮换令牌。
- 设备与分享列表、撤销接口只操作认证设备当前空间；资源 ID 跨空间访问统一返回 404。
- V004 创建默认旧空间并归属现有设备、剪贴记录、分享、配对码和同步状态，保留旧设备 ID、令牌哈希、数据与同步序号。
- REST、WebSocket、序号、同步下界和保留清理均按空间隔离；客户端不提交空间 ID。

## 4. 验收场景

| 场景 | 验收结果 |
| --- | --- |
| 旧数据升级 | 迁移后原设备、历史记录、分享和令牌仍属于同一个默认旧空间；旧客户端仍能同步该空间数据。 |
| 空间隔离 | 两个空间各有设备和剪贴记录；任一空间无法读取、修改或删除另一空间的记录、设备、分享；猜测其他空间资源 ID 不泄露其存在状态。 |
| 多码加入同空间 | 同一空间内两台成员设备分别生成不同的一次性配对码；使用任一码加入的新设备都进入同一空间并收到该空间数据。 |
| 空间内同步 | 一个成员创建设备或剪贴记录时，事件只发送给同空间设备；空间内序号连续，其他空间的事件不会造成同步缺口。 |
| 设备标识重装 | Android、iOS、Desktop 分别验证安装、卸载、重装后的设备标识行为；令牌丢失时只凭设备标识不能认证，必须重新配对。 |
| 设备撤销 | 撤销后目标设备的新 REST 请求失败，现有 WebSocket 被关闭；其他成员和空间数据不受影响。 |
| 最后一台设备 | 删除最后设备前出现明确二次确认；确认后空间在线数据被删除；备份仍按现行保留策略存在，文案说明备份恢复可能恢复旧空间数据。 |
| 分享撤销 | 空间成员可定位并撤销有效分享；撤销后原 URL 返回无效/不存在状态，其他空间的分享不受影响。 |
| 工具箱 | JWT 显示解码结果并明确不验证签名；SHA-256 与 UUID/ULID 在断网状态下可用，输入输出不进入历史或网络请求。 |

## 5. 约束、风险与默认值

- 稳定设备标识不是跨平台永久保证。Android 的 `ANDROID_ID` 受签名密钥、用户和设备范围影响，并可能在恢复出厂等情况下变化；Apple 的 `identifierForVendor` 会在用户移除该厂商全部 App 后变化。实现后按任务卡手工验证卸载重装表现并记录平台差异：[Android 文档](https://developer.android.com/reference/android/provider/Settings.Secure.html)、[Apple 文档](https://developer.apple.com/documentation/uikit/uidevice/identifierforvendor)。
- 账号在本版指配对设备组成的共享空间，不等于用户名密码账号。客户端每次只关联一个空间；换空间需先解除当前关联，再创建或加入其他空间，并明确本地数据清除行为。
- 最后一台设备删除空间的操作不可撤销在线数据；必须二次确认。备份保留与可能恢复旧空间数据的风险按本提案接受，不承诺从历史整库备份中即时擦除租户数据。
- 不新增应用权限或第三方分析、崩溃 SDK；不记录设备标识、配对码、访问令牌、分享令牌、剪贴正文或工具输入输出。
- 文案继续通过 Compose Resources 提供简体中文、繁體中文、English；服务端仍按现有学习版 HTTP/IP 部署基线运行。
- 冻结后的实现契约见 [功能需求文档](功能需求文档.md)、[api.md](api.md)、两份技术架构、[ADR-0011](adr/0011-multi-space-and-device-identity.md) 与 [T-V12 任务卡](tasks/08-v12.md)。
