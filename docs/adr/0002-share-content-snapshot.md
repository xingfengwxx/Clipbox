# 分享页保存内容快照

**Status**: accepted

## Context

分享页需要在有效期内对任意浏览器只读展示一条剪贴记录。若只存 `clip_id` 引用，记录被删除或按保留策略清理后，未过期的分享链接会提前失效；若保存快照，则分享生命周期与记录解耦。单条上限 64 KiB、默认 24 小时过期，存储成本可忽略。

## Decision

创建分享时把剪贴记录内容快照写入 `shares.content`，同时保留 `clip_id` 用于追踪来源。分享页只读快照，不联查剪贴记录；删除或清理剪贴记录不影响已生成的分享，直到过期或阅后即焚。v1.0.0 不提供主动撤销分享。

## Considered Options

- 仅引用 clip_id：实现简单，但记录删除会导致分享提前失效，行为不可预期。
- 快照 + 删除记录时级联撤销：语义更强，但需要额外的撤销逻辑与用户提示，超出 v1.0.0 范围。

## Consequences

- `shares` 表增加 `content` 字段；分享页渲染不依赖 `clips` 表。
- 若未来需要“删记录即撤链”，应新增显式撤销接口，而不是回退到引用模式。
