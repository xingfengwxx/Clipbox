# 多空间隔离与设备安装标识

**Status**: accepted

## Context

v1.1 服务端把所有设备、剪贴记录、分享、配对码和同步游标放在一个隐式共享空间中。v1.2 需要允许同一服务端承载多个互相隔离的空间，同时保留旧客户端、旧设备令牌与已有数据。设备管理还需要区分长期服务端设备记录与可能随平台条件改变的本地安装标识。

## Decision

- 引入服务端管理的空间实体。创建空间时与首台设备原子写入；配对码绑定签发设备所属空间；客户端不提交空间 ID，所有认证数据操作由服务端从设备令牌解析空间。
- 迁移现有数据库时创建默认旧空间，并把旧设备、剪贴记录、分享、配对码及同步状态归入其中。保留设备 ID、令牌哈希、记录与分享访问令牌哈希；旧设备令牌只访问默认旧空间。
- 新增可选的 `installationId` 请求字段。服务端 `deviceId` 仍是设备主键和 API 标识；安装标识只作设备元数据，不参与认证、空间选择或令牌恢复。
- Android 使用 `Settings.Secure.ANDROID_ID`，iOS 使用 `identifierForVendor`，Desktop 在本地持久化随机 UUID。标识变化视为新设备；使用有效同空间配对码重配时，复用该空间的设备行并轮换令牌。
- `serverSeq`、`sync_floor`、剪贴记录 ID 唯一性、保留清理和 WebSocket 广播按空间隔离。跨空间资源访问统一返回 404。
- 新增当前空间设备与分享管理接口。分享管理 ID 独立随机生成，绝不替代或暴露分享访问令牌。撤销末台设备会在事务中删除该空间在线数据；备份按现有整库周期保留。
- 保留 `/api/v1/bootstrap` 仅空数据库初始化语义以兼容旧客户端；v1.2 新客户端提供显式“创建空间”与“输入配对码加入”流程。

## Considered Options

- **引入用户账号表与登录**：能为多个空间提供云端所有者，但引入账号凭据、找回与服务端身份系统，超出 v1.2 自托管配对模型。
- **让客户端选择并提交空间 ID**：接口简单，但会把租户隔离依赖在每个调用方输入上，容易产生越权查询。
- **把安装标识用作认证凭据或 `deviceId` 主键**：安装标识可能重置或被伪造，不能授予访问；替换现有服务端 ID 还会破坏来源设备引用与旧客户端兼容。
- **全局序号与全局唯一剪贴 ID**：实现变化较少，但会在跨空间写入冲突和同步游标中泄露其他空间状态，不能满足隔离要求。

## Consequences

- SQLite 迁移 V004 增加空间归属、安装标识、分享管理 ID 和按空间同步状态；剪贴主键和序号唯一约束包含 `space_id`。
- REST、WebSocket、配对码签发、分享访问管理与保留清理必须经由已解析的空间上下文。
- 旧客户端可继续操作迁移后的默认旧空间；新空间只对其成员设备令牌可见。
- 设备标识有平台生命周期边界。安装标识改变或令牌丢失时需要重新配对；仅标识不能恢复访问。
- 删除末台设备可删除在线空间数据，但历史整库备份可能恢复该空间，必须在确认界面说明。
- v1.2 不引入账号登录、跨空间选择器、额外权限或第三方分析/崩溃 SDK。
