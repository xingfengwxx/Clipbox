## 1. 优先级与需求编号

### 1.1 优先级定义

交接文档中的 P0 / P1 / P2 描述的是产品阶段，本文档将其映射为 v1.0.0 的交付范围：

| 本文档标记 | 含义                     | 与交接文档对应 |
| ---------- | ------------------------ | -------------- |
| `P0`       | v1.0.0 核心功能，必须交付 | 交接文档 P0    |
| `P1`       | v1.0.0 扩展功能，必须交付 | 交接文档 P1（仅分享链接与工具箱） |
| `P2`       | v1.0.0 不交付，仅保留路线 | 交接文档 P1 剩余项与 P2 |

> 注意：交接文档 P1 中的「片段收藏夹」和「Android 后台通知」在 v1.0.0 中调整为 P2（见 §8）。

### 1.2 编号规则

`REQ-<域>-<三位序号>`，域取值：

| 域     | 范围             |
| ------ | ---------------- |
| `PAIR` | 配对与设备       |
| `SEND` | 文本发送         |
| `RECV` | 文本接收         |
| `HIST` | 历史记录         |
| `SYNC` | 同步与离线       |
| `SHARE`| 分享链接         |
| `TOOL` | 工具箱           |
| `SET`  | 设置             |
| `PLAT` | 平台与运行环境   |
| `NFR`  | 非功能需求       |

### 1.3 端标记

| 标记 | 含义                     |
| ---- | ------------------------ |
| `A`  | Android 客户端           |
| `D`  | Desktop 客户端           |
| `S`  | 服务端                   |
| `All`| 双端或全链路             |

### 1.4 验收写法

每条需求附 Given / When / Then 形式的验收条件。可测试的数值（时限、条数、字节数）均为硬性指标，测试结果需可复现。

## 2. 产品目标与用户角色

### 2.1 产品目标

1. 让同一用户在 Android 与 Desktop 之间传递文本时，不需要登录网页、发消息给自己或依赖第三方应用。
2. 桌面端收到文本后能自动写入系统剪贴板，实现「手机分享 → 桌面 Ctrl+V」的闭环。
3. 无网络或服务端不可用时，客户端仍可发送、查看、搜索、置顶、删除历史，恢复后自动补同步。
4. 在本地提供开发者高频使用的小工具，且工具箱完全离线、零权限。

### 2.2 用户角色

只有一种角色：**单用户，多设备**。

- 用户拥有一个「用户空间」，通过配对将多台设备绑定到同一空间。
- 不存在注册、登录、邀请他人、共享空间、多租户隔离。
- 设备之间数据完全互通；任一设备可查看、置顶、删除全部历史。

### 2.3 典型场景

| 场景     | 描述                                                         |
| -------- | ------------------------------------------------------------ |
| 手机到桌面 | 手机上看到一段验证码 / 链接 / 报错日志，分享到 Clipbox，桌面直接粘贴 |
| 桌面到手机 | 桌面复制命令或配置片段，手机打开 App 一键复制                |
| 长文本分享 | 把一段日志或 SQL 生成只读链接，在任意浏览器打开，可设一次性  |
| 离线使用 | 地铁里无网络，仍可写入、搜索、置顶、删除，出站后自动同步     |
| 本地工具 | 格式化 JSON、解码 Base64、转换时间戳，不联网、不上传         |

## 3. 范围

### 3.1 v1.0.0 交付范围

- 设备配对与本地令牌管理。
- Android 三种发送入口：系统分享、文本选中菜单、App 内输入框。
- Desktop 两种发送入口：窗口输入框、系统剪贴板自动发送（默认关闭）。
- Desktop WebSocket 实时接收并自动写入系统剪贴板（默认开启）。
- Android 前台同步接收、一键复制。
- 历史记录：展示、搜索、置顶、删除、失败标记。
- 离线队列与自动重试、断线重连与增量补拉。
- 一次性分享链接与只读网页。
- 工具箱 5 个纯本地工具。
- 设置页：服务器地址、配对、自动粘贴、自动发送、主题、立即同步、解除配对、关于。
- 服务端 Docker Compose + Caddy 部署，HTTPS / WSS。

## 4. 功能需求

### 4.1 配对与设备（PAIR）

#### REQ-PAIR-001 生成配对码（P0，S）

服务端提供管理接口生成 6 位数字配对码，有效期 10 分钟，一次性使用。

- 配对码只通过管理接口生成，客户端不能自行生成。
- 管理接口需要 `X-Admin-Token`，令牌错误返回 401。
- 服务端启动时若不存在「未使用且未过期」的配对码，自动生成一个并打印到容器日志，便于自助配对。
- 配对码字符集为 `0-9`，允许前导零。

**验收**

- Given 服务端已启动且配置了 `ADMIN_TOKEN`，When 调用生成接口，Then 返回 201 与 `code`、`expiresAt`，`code` 为 6 位数字，`expiresAt` 为当前时间 + 600 秒。
- Given 请求未携带或携带错误的 `X-Admin-Token`，When 调用生成接口，Then 返回 401，不生成配对码。

#### REQ-PAIR-002 输入配对码完成配对（P0，All）

用户在新设备上输入服务器地址与配对码，完成配对后获得设备令牌。

- 客户端需同时填写设备名称，默认值为 `Android · <型号>` 或 `Desktop · <系统 / 主机名>`，可编辑。
- 设备名称长度 1–64 字符，去除首尾空白后不能为空。
- 配对成功后客户端立即持久化设备令牌，后续启动无需重新配对。
- 配对成功后客户端用返回的 `deviceId` 标识本机，用于历史记录的来源展示与剪贴板回环抑制。

**验收**

- Given 服务端存在有效配对码，When 客户端提交正确的服务器地址、配对码与设备名称，Then 返回 201，客户端进入已配对状态，令牌写入本地安全存储。
- Given 配对成功，When 重启客户端，Then 仍处于已配对状态，不需要重新输入配对码。

#### REQ-PAIR-003 配对码错误与过期提示（P0，All）

配对失败必须给出可区分的中文提示，不能只显示「配对失败」。

| 情况                         | 提示文案（可微调，语义不变）       |
| ---------------------------- | ---------------------------------- |
| 配对码不存在                 | 配对码无效，请检查后重试           |
| 配对码已过期                 | 配对码已过期，请重新获取           |
| 配对码已被使用               | 配对码已被使用，请重新获取         |
| 设备名称不合法               | 设备名称需为 1–64 个字符           |
| 网络不可达                   | 无法连接服务器，请检查地址与网络   |
| 服务器地址不是 HTTPS（非 localhost） | 正式环境必须使用 HTTPS     |

**验收**

- Given 配对码已过期，When 用户提交，Then 客户端展示「配对码已过期」，停留在配对页，已填内容不丢失。
- Given 服务器返回 429，When 用户提交，Then 客户端展示「尝试过于频繁，请稍后再试」，并禁用提交按钮直到冷却结束。

#### REQ-PAIR-004 配对失败限速（P0，S）

服务端按来源 IP 限制配对请求，5 次 / 分钟 / IP（含成功与失败），超出返回 429。

- 限速窗口内只统计实际到达 `/api/v1/pair` 的请求，管理接口单独限速。
- 反向代理场景下需基于可信代理头解析真实 IP，且不能信任任意来源的 `X-Forwarded-For`。

**验收**

- Given 同一 IP 在 1 分钟内已发起 5 次配对请求，When 发起第 6 次，Then 返回 429，且不消耗任何有效配对码。
- Given 触发 429，When 等待限速窗口结束，Then 可以正常配对。

#### REQ-PAIR-005 多设备绑定（P0，All）

同一用户空间可绑定多台设备，设备之间数据互通。

- 每台设备有独立的 `deviceId` 与令牌。
- 广播事件会发送给所有已认证设备，包括触发写入的设备自身（用于统一 seq 推进）。
- 历史记录展示来源设备名称；本机记录显示「本机」；来源设备已不存在时展示「未知设备」。

**验收**

- Given 已配对手机 A 与桌面 D，When A 发送一条文本，Then 服务端广播 `clip.created` 给 A 与 D，D 收到后写入剪贴板；A 的历史列表出现该记录且来源显示「本机」，D 显示 A 的设备名。
- Given 三台设备均已配对，When 任一设备发送，Then 其余两台均能实时或打开 App 后收到。

#### REQ-PAIR-006 解除配对（P0，All）

设置页提供「解除配对」，清除本地令牌与本地数据。

- 解除配对前必须二次确认，明确提示「本地历史将被清空，服务端数据保留」。
- 解除配对只清除本机凭据与本地库，不调用服务端删除接口，不影响其他设备。
- 解除后 App 回到配对页，停止同步与 WebSocket。

**验收**

- Given 设备已配对，When 用户确认解除配对，Then 本地令牌、历史、outbox、游标全部清除，App 展示配对页。
- Given 设备 A 解除配对，When 设备 B 继续使用，Then B 的数据与同步不受影响。

#### REQ-PAIR-007 更换服务器地址（P0，All）

设置页允许修改服务器地址。

- 修改地址必须重新配对：旧令牌对新服务器无效，客户端清除旧令牌并跳转配对页。
- 修改前二次确认，提示将清空本地数据。

**验收**

- Given 客户端已配对服务器 S1，When 用户把地址改为 S2 并确认，Then 本地旧数据被清除，App 要求重新配对。
- Given 输入的地址非法（缺少 scheme、包含空格），When 保存，Then 提示格式错误，不发起请求。

#### REQ-PAIR-008 未配对时的分享处理（P0，A）

Android 在未配对状态下收到系统分享时，不能静默丢弃文本。

- 未配对时打开 App 的配对页，同时把分享文本暂存为本地草稿。
- 配对成功后自动跳转发送页并预填该草稿，由用户确认发送。
- 草稿只保留最近一条，新的分享覆盖旧草稿；用户发送后清除，取消编辑则保留，下次进入仍可见。

**验收**

- Given App 未配对，When 用户从其他应用分享文本到 Clipbox，Then 打开配对页，配对完成后输入框预填该文本。
- Given 已存在未发送草稿，When 用户再次分享新文本，Then 草稿更新为新文本。

### 4.2 文本发送（SEND）

#### REQ-SEND-001 Android 系统分享入口（P0，A）

Clipbox 注册 `ACTION_SEND` + `text/plain`，出现在系统分享面板。

- 收到分享后进入发送页，文本预填，用户可编辑后发送。
- 分享文本超过 64 KiB 时，进入页面即提示超限，发送按钮禁用，并提供「复制到剪贴板」作为降级出口。
- 分享 Intent 中无文本时展示空状态提示，不崩溃。

**验收**

- Given 手机已配对，When 在浏览器选中文本并分享到 Clipbox，Then 打开发送页且输入框预填该文本，点击发送后记录出现在历史列表。
- Given 分享文本为 70 KiB，When 进入发送页，Then 提示「文本超过 64 KiB 上限」，发送按钮不可用。

#### REQ-SEND-002 Android 文本选中菜单（P0，A）

Clipbox 注册 `ACTION_PROCESS_TEXT`，出现在文本选中菜单中。

- 行为与 REQ-SEND-001 一致：进入发送页、预填、可编辑、可发送。
- 只处理 `text/plain`，其他 MIME 类型不显示入口。
- 发送成功后向系统返回原文本，避免替换用户选中的文本。

**验收**

- Given 在任意支持 `ACTION_PROCESS_TEXT` 的应用中选中文本，When 选择 Clipbox，Then 打开发送页并预填选中文本。

#### REQ-SEND-003 App 内输入框发送（P0，All）

历史页顶部提供输入框与发送按钮。

- 发送前去除首尾空白；去除后为空则禁止发送。
- 发送成功后清空输入框，新记录插入非置顶区顶部。
- 发送失败（离线）时记录仍出现在列表顶部，并标记为待同步。
- 支持多行输入，输入框高度自适应，最大占屏幕 1/3。

**验收**

- Given 用户在输入框输入 `hello`，When 点击发送，Then 输入框清空，列表顶部出现 `hello`，状态由待同步变为已同步。
- Given 输入内容只有空格，When 查看发送按钮，Then 按钮禁用。

#### REQ-SEND-004 Desktop 剪贴板自动发送（P0，D）

Desktop 可监听系统剪贴板并自动发送文本，默认关闭。

- 开启后每 500ms 轮询系统剪贴板，内容变化且为文本时触发。
- 触发后 debounce 800ms，期间内容再次变化则重新计时，避免连续复制产生多条记录。
- 单次自动发送的文本同样受 64 KiB 上限约束，超限时只提示不发送，且不重复提示同内容。
- 关闭开关后立即停止监听，不残留定时任务。

**验收**

- Given 自动发送已开启，When 用户在任意应用复制一段文本并等待 2 秒，Then 历史列表新增该文本记录。
- Given 自动发送已开启，When 用户在 800ms 内连续复制 3 次，Then 只产生 1 条记录，内容为最后一次复制的内容。
- Given 自动发送默认状态，When 首次进入设置页，Then 开关为关闭。

#### REQ-SEND-005 发送采用本地优先（P0，All）

所有发送先写本地库，再异步同步，弱网或离线不阻塞 UI。

- 点击发送后 UI 在 100ms 内完成列表插入与输入框清空，不等待网络。
- 网络请求在后台执行，成功后更新同步状态，不改变列表顺序。
- 同一条记录不允许因重试产生重复。

**验收**

- Given 设备处于飞行模式，When 用户发送文本，Then 记录立即出现在列表并标记待同步，无错误弹窗。
- Given 恢复网络，When 后台重试成功，Then 记录标记变为已同步，服务端仅存在一条该记录。

#### REQ-SEND-006 发送内容校验（P0，All）

客户端与服务端都必须校验单条文本上限 64 KiB（UTF-8 字节数）。

- 客户端按 UTF-8 编码后的字节数计算，不是字符数。
- 超限时客户端拦截并提示，不发请求。
- 服务端独立校验，正文超过 64 KiB 返回 400 与 `VALIDATION_ERROR`。
- 服务端请求体上限为 512 KiB，用于容纳 JSON 转义膨胀；超过请求体上限返回 413 与 `PAYLOAD_TOO_LARGE`。

**验收**

- Given 输入 65536 字节的 ASCII 文本，When 发送，Then 成功。
- Given 输入 65537 字节的文本，When 发送，Then 客户端提示超限，不发起请求。
- Given 绕过客户端直接 POST 70 KiB 文本，When 服务端处理，Then 返回 400 与 `VALIDATION_ERROR`。

#### REQ-SEND-007 发送反馈（P0，All）

发送动作必须有明确反馈。

- 成功：列表插入 + 轻量提示（Toast / Snackbar）。
- 失败且可重试：条目标记待同步，不打断用户。
- 失败且不可重试（如 413、400）：条目标记失败，展示原因，提供「删除」与「重试」操作。
- 不允许出现「无任何反馈」的发送。

**验收**

- Given 服务端返回 400（正文超限），When 用户发送，Then 条目显示失败标记，点击可查看「内容超过上限」并删除。
- Given 服务端不可达，When 用户发送，Then 条目显示待同步，网络恢复后自动变为已同步。

#### REQ-SEND-008 发送后不自动复制（P0，All）

发送方设备不因自己发送的内容而改写入系统剪贴板。

- 服务端会把事件广播给发送方，客户端必须识别 `sourceDeviceId == 本机 deviceId` 并跳过自动粘贴。
- 该规则同样适用于 Desktop 的收包自动写入逻辑。

**验收**

- Given 桌面已开启自动粘贴，When 在桌面输入框发送文本，Then 系统剪贴板内容不被该文本覆盖。

#### REQ-SEND-009 超长文本的降级出口（P0，All）

超过 64 KiB 的文本不能被发送，但必须提供本地复制作为降级出口。

- Android 分享入口超限时提供「复制到剪贴板」。
- Desktop 输入框超限时提示并禁用发送，提供「复制到剪贴板」。
- 超限文本无法入库，因此不提供生成分享链接的入口。

**验收**

- Given 文本 70 KiB，When 用户尝试发送，Then 明确提示上限为 64 KiB，并提供复制到剪贴板。

### 4.3 文本接收（RECV）

#### REQ-RECV-001 Desktop WebSocket 实时接收（P0，D）

Desktop 启动后建立并保持 WebSocket 连接，实时接收其他设备的新记录。

- 连接成功后用 `auth.ok` 返回的 `serverSeq` 校准本地游标；若服务端序号大于本地，触发增量补拉。
- 收到 `clip.created` 时写入本地库并刷新列表，不要求用户手动刷新。
- 收到 `clip.updated` / `clip.deleted` 时同步更新本地状态（置顶、删除）。
- 事件中的 `seq` 不连续时，忽略该事件并触发 REST 补拉；补拉期间收到的事件先缓冲，补拉结束后按序处理。

**验收**

- Given Desktop 在线且 WebSocket 已连接，When 手机发送文本，Then Desktop 在 5 秒内展示该记录。
- Given WebSocket 收到 `seq=105` 而本地 `lastSeq=103`，When 客户端检测到缺口，Then 发起 `since=103` 补拉，补拉完成后列表完整且无重复。

#### REQ-RECV-002 Desktop 自动写入剪贴板（P0，D）

Desktop 收到远端记录后自动写入系统剪贴板，默认开启。

- 只对「其他设备」通过 WebSocket 实时创建的记录写入，不处理 REST 补拉的历史记录，避免覆盖用户当前剪贴板。
- 连续收到多条时逐条写入，后到的内容覆盖先到的，最终以最后一条为准。
- 写入失败（剪贴板被占用）时保留记录并提示「自动复制失败，请手动复制」，不重试写入。
- 设置页可关闭该能力，关闭后仅入库不写剪贴板。

**验收**

- Given 自动粘贴开启，When 手机发送文本，Then Desktop 系统剪贴板内容变为该文本，并提示已复制。
- Given 自动粘贴关闭，When 手机发送文本，Then Desktop 列表出现记录，系统剪贴板不变。
- Given 应用启动后补拉 10 条历史，When 补拉完成，Then 系统剪贴板不被这些旧记录改写。

#### REQ-RECV-003 Android 前台同步接收（P0，A）

Android 在 App 进入前台时同步，展示最新记录。

- `onResume` 或进入前台时用游标增量补拉。
- 前台期间可建立 WebSocket 以实时接收；退到后台后断开，不做后台常驻。
- 不做后台剪贴板写入，不发送通知。

**验收**

- Given 手机 App 在后台，When 桌面发送文本，Then 手机不弹通知、不写剪贴板。
- Given 手机回到前台，When 同步完成，Then 列表顶部出现桌面发送的记录，3 秒内可见。

#### REQ-RECV-004 Android 一键复制（P0，A）

列表项提供复制按钮，点击后写入系统剪贴板并提示。

- 复制成功提示「已复制」。
- Android 13+ 系统会自动展示剪贴板预览，App 不重复弹窗遮挡。
- 复制动作不改变记录的同步状态，不触发上传。

**验收**

- Given 列表中存在记录，When 点击复制，Then 剪贴板内容等于该记录内容，出现「已复制」提示。

#### REQ-RECV-005 剪贴板回环防护（P0，D）

桌面自动粘贴与自动发送同时开启时，不能形成「写入 → 监听 → 上传」的无限循环。

- 记录 `lastAppliedHash`（最后写入剪贴板的内容哈希）与 `lastSentHash`（最后上传的内容哈希）。
- 监听回调命中 `lastAppliedHash` 且在 2 秒时间窗内时跳过。
- 写入剪贴板前记录哈希，写入后更新 `lastAppliedHash`。
- 回环防护必须在自动粘贴与自动发送同时开启时生效。

**验收**

- Given 自动粘贴与自动发送均开启，When 手机发送文本到桌面，Then 桌面写入剪贴板后不产生新的上传记录。
- Given 防护生效，When 2 秒后用户手动复制同样的内容，Then 仍可正常发送（不被永久屏蔽）。

#### REQ-RECV-006 远端置顶 / 删除的实时反映（P0，All）

其他设备对记录执行置顶或删除后，本机列表需在同步后反映。

- 在线时通过 WebSocket 事件即时反映。
- 离线后重新联网通过增量补拉反映。
- 已删除记录不出现在列表，即使本地仍保留墓碑。

**验收**

- Given 桌面已删除记录 R，When 手机在线，Then 手机列表在 5 秒内移除 R。
- Given 手机离线期间桌面删除 R，When 手机恢复网络并同步，Then R 从手机列表消失。

#### REQ-RECV-007 新记录提示（P0，All）

App 不在当前列表页或列表未滚动到顶部时，收到新记录应有非打扰提示。

- 当前位于历史页且列表在顶部：直接插入，不额外提示。
- 位于其他页面：展示 Snackbar「收到新记录」，点击跳转历史页顶部。
- 提示不阻塞操作，3 秒自动消失。

**验收**

- Given 用户停留在工具箱页，When 收到新记录，Then 出现「收到新记录」提示，点击后回到历史页并看到该记录。

#### REQ-RECV-008 剪贴板写入失败处理（P0，D）

系统剪贴板不可用时，不能丢失记录或崩溃。

- 捕获异常，记录日志（不含文本内容），提示用户手动复制。
- 在列表项上标记「自动复制失败」，用户可手动点击复制重试。

**验收**

- Given 剪贴板被其他程序独占导致写入异常，When 收到新记录，Then 记录正常入库，提示自动复制失败，手动复制可成功。

### 4.4 历史记录（HIST）

#### REQ-HIST-001 历史列表展示范围（P0，All）

客户端展示最近 200 条非置顶记录，以及全部置顶记录。

- 置顶记录不占用 200 条配额。
- 服务端保留 500 条非置顶 + 全部置顶；客户端只展示 200 条非置顶是产品选择，不是数据丢失。
- 客户端本地可按同一规则清理，但本地清理不得向服务端传播删除。

**验收**

- Given 服务端有 600 条非置顶记录，When 客户端完成同步，Then 客户端列表最多展示 200 条非置顶记录，且均为最新的 200 条。
- Given 用户置顶 30 条记录，When 列表加载，Then 置顶区展示 30 条，非置顶区仍展示 200 条。

#### REQ-HIST-002 列表项信息（P0，All）

每条记录展示以下信息：

| 字段       | 说明                                             |
| ---------- | ------------------------------------------------ |
| 内容预览   | 最多 3 行，超出省略；保留换行                     |
| 来源设备   | 设备名称；本机显示「本机」；未知显示「未知设备」 |
| 时间       | 相对时间（刚刚 / 5 分钟前 / 昨天 / 日期）        |
| 置顶标记   | 置顶记录在列表顶部并有图标                       |
| 同步状态   | 待同步 / 失败时展示角标；已同步不展示            |

**验收**

- Given 一条 500 字的多行文本，When 展示在列表，Then 最多显示 3 行并以省略号结尾。
- Given 一条待同步记录，When 展示，Then 显示待同步角标；同步成功后角标消失。

#### REQ-HIST-003 列表操作（P0，All）

每条记录支持：复制、置顶 / 取消置顶、删除、生成分享链接（仅已同步）。

- 复制：写入系统剪贴板并提示。
- 置顶：立即置顶并同步；再次点击取消置顶。
- 删除：二次确认后本地移除并同步软删除。
- 分享：仅已同步记录可生成链接；待同步 / 失败记录禁用并提示原因。

**验收**

- Given 一条已同步记录，When 点击置顶，Then 记录移动到列表顶部，重启 App 后仍置顶。
- Given 一条待同步记录，When 打开操作菜单，Then「生成分享链接」为禁用状态并提示「同步后可分享」。

#### REQ-HIST-004 排序规则（P0，All）

列表排序固定为：置顶记录在前，组内按创建时间倒序。

- 置顶不改变记录的创建时间。
- 补拉的历史记录按创建时间插入正确位置，不一律置顶。
- 同毫秒创建时按 `id` 字典序倒序，保证顺序稳定。

**验收**

- Given 置顶记录 P 创建于 3 天前，新记录 N 创建于现在，When 展示列表，Then P 在 N 之前。
- Given 补拉 5 条旧记录，When 插入列表，Then 它们位于对应时间位置，不覆盖最新记录。

#### REQ-HIST-005 搜索（P0，All）

历史页提供搜索框，对内容做本地包含匹配。

- 输入后 300ms 防抖执行，不请求服务端。
- 大小写不敏感；支持中文与 emoji。
- 搜索范围：本地已加载的全部记录（200 条非置顶 + 置顶）；不搜索服务端未同步到本地的记录。
- 无结果时展示空状态「没有匹配的记录」。
- 清空搜索框恢复完整列表与滚动位置。

**验收**

- Given 本地有包含 `Hello` 的记录，When 搜索 `hello`，Then 能匹配到该记录。
- Given 搜索无结果，When 查看页面，Then 展示「没有匹配的记录」，不展示错误。

#### REQ-HIST-006 置顶（P0，All）

置顶状态跨设备同步，且不参与服务端自动清理。

- 置顶操作本地立即生效，写入 outbox。
- 服务端更新 `pinned` 并推进 `serverSeq`，广播 `clip.updated`。
- 重复设置相同值不推进序号、不产生额外广播。
- 置顶记录永久保留，除非用户删除。

**验收**

- Given 记录 R 未置顶，When 在手机置顶，Then 桌面在 5 秒内看到 R 移动到置顶区。
- Given R 已置顶，When 再次置顶，Then 服务端不返回新的 `serverSeq` 变化（或返回相同值），不产生重复事件。

#### REQ-HIST-007 删除（P0，All）

删除为软删除，跨设备同步，不可撤销。

- 删除前二次确认：「删除后无法恢复」。
- 本地立即移除并标记待删除，写入 outbox。
- 服务端设置 `deleted_at` 并推进 `serverSeq`，广播 `clip.deleted`。
- 重复删除同一记录按幂等处理，返回已有 `serverSeq`。
- 已删除记录不再出现在任何端列表。
- v1.0.0 不提供撤销与回收站。

**验收**

- Given 记录 R 存在，When 用户确认删除，Then R 从本机列表消失，其他在线设备 5 秒内移除。
- Given R 已删除，When 再次调用删除接口，Then 返回成功且不报错，不产生新的序号推进。

#### REQ-HIST-008 离线操作（P0，All）

离线时置顶、删除、发送均可执行，恢复后按顺序重放。

- 操作立即在本地生效，进入 outbox。
- outbox 持久化，App 重启不丢。
- 恢复网络后按入队顺序重放；同一记录的多笔操作严格有序执行。
- 重放失败按 REQ-SYNC-004 的策略重试或标记失败。

**验收**

- Given 离线状态下置顶 R 并删除 S，When 重启 App，Then 两笔操作仍在队列中；恢复网络后服务端状态与本地一致。

#### REQ-HIST-009 空态、加载态与错误态（P0，All）

三种状态必须有明确 UI。

| 状态   | 展示                                                         |
| ------ | ------------------------------------------------------------ |
| 空态   | 插画 + 「还没有记录」+「从手机分享或在上方输入开始」         |
| 加载态 | 首次加载展示骨架屏或进度条，不展示空白页                     |
| 错误态 | 展示「同步失败」+ 原因 + 「重试」按钮；已加载的本地数据继续展示 |

**验收**

- Given 首次启动且无记录，When 列表加载完成，Then 展示空态文案。
- Given 服务端不可达但本地有记录，When 打开 App，Then 仍展示本地记录，同时展示同步失败提示与重试按钮。

#### REQ-HIST-010 本地清理不影响服务端（P0，All）

客户端为控制本地体积可只保留 200 条非置顶记录，但不得把本地清理当作删除同步到服务端。

- 本地清理只删除 `SYNCED` 状态且非置顶的记录。
- 清理不写入 outbox，不调用删除接口。
- 被本地清理的记录若在服务端被修改（置顶 / 删除），客户端通过补拉仍能正确处理（记录可能重新出现或保持不存在）。

**验收**

- Given 客户端本地清理了第 201 条记录，When 查看服务端，Then 该记录仍在服务端且未被标记删除。

#### REQ-HIST-011 失败记录处理（P0，All）

因内容或权限等原因永久失败的记录必须可被用户处理。

- 列表项展示失败原因（如「内容超过上限」「服务器拒绝」）。
- 提供「重试」与「删除」操作。
- 重试会重置重试计数并立即发起一次请求。
- 失败记录不阻塞其他记录的同步。

**验收**

- Given 记录因 400（正文超限）失败，When 用户点击重试，Then 仍失败并保持失败态；点击删除后记录消失。

### 4.5 同步与离线（SYNC）

#### REQ-SYNC-001 本地库为唯一数据源（P0，All）

所有页面只读本地库，不直接渲染网络响应。

- 网络请求只负责更新本地库。
- 列表、搜索结果、置顶状态均来自本地查询。
- 进程重启后，在无网络情况下也能展示上次同步的数据。

**验收**

- Given 已同步 100 条记录，When 断网后重启 App，Then 仍展示 100 条记录。

#### REQ-SYNC-002 写入路径（P0，All）

写入遵循「本地落库 → 入 outbox → 异步上传 → 标记已同步」。

- 本地落库与入队在同一事务中完成。
- 上传成功后按服务端返回的 `serverSeq` 更新本地记录，再标记 `SYNCED`。
- HTTP 写响应中的 `serverSeq` 不得直接推进全局 `lastSeq`，避免跳过其他设备的事件。
- 上传失败保留在 outbox 并更新重试信息。

**验收**

- Given 用户发送文本，When 上传成功，Then 本地记录状态为 `SYNCED`，且全局 `lastSeq` 未因该响应跳变。

#### REQ-SYNC-003 outbox 持久化（P0，All）

outbox 必须落盘，进程被杀后重启继续重放。

- 每条操作记录：操作类型、目标 `clipId`、payload、重试次数、下次重试时间、最后错误码。
- 启动时扫描到期操作并恢复重放。
- 已成功的操作从 outbox 删除，不做长期归档。

**验收**

- Given 离线发送 3 条文本后强杀 App，When 重新打开并联网，Then 3 条文本全部上传成功，服务端无重复。

#### REQ-SYNC-004 重试策略（P0，All）

网络类失败按指数退避重试，1s → 2s → 4s … 上限 60s。

- 加入 ±20% 抖动，避免多设备同时重试。
- 429 优先使用响应中的 `Retry-After`。
- 401 暂停同步并提示重新配对，不继续重试。
- 400 / 409 / 413 / 415 视为永久失败，标记 `FAILED_*`，等待用户处理。
- 5xx 与超时按网络类失败处理。

**验收**

- Given 服务端持续 503，When 客户端重试，Then 间隔符合指数退避且不超过 60s。
- Given 服务端返回 401，When 客户端收到，Then 停止重试并提示重新配对。

#### REQ-SYNC-005 增量拉取（P0，All）

客户端使用 `since` 游标增量拉取变更。

- `since=0` 表示全量同步，用于首次配对或本地数据被清空。
- 每次拉取成功后把 `lastSeq` 推进到响应中的 `nextSince`。
- `limit` 默认 200，最大 500；`hasMore=true` 时继续拉取直到追平。
- 拉取结果按 `id` upsert，保证幂等。

**验收**

- Given 本地 `lastSeq=100`，When 服务端有 101–150 的变更，Then 客户端用 `since=100` 拉取并推进到 150。
- Given 同一批数据被拉取两次，When 入库，Then 不产生重复记录。

#### REQ-SYNC-006 WebSocket 断线与重连（P0，D，A 前台）

连接异常时必须自动重连并用游标补拉。

- 重连采用指数退避，1s 起，上限 60s，无限重试直到成功或用户解除配对。
- 例外：收到 4401（令牌失效）时停止重连并提示重新配对；收到 4001（被同设备新连接替换）时停止重连，避免两个实例互踢。
- 重连成功后用 `auth.ok.serverSeq` 与本地 `lastSeq` 比较，落后则补拉。
- 断线期间不丢事件：服务端不重放，客户端靠补拉补齐。
- 主动退到后台（Android）不提示错误；回到前台重新连接。

**验收**

- Given Desktop 断网 2 分钟，期间手机发送 5 条，When 网络恢复，Then Desktop 自动重连并补拉出 5 条，顺序正确，无重复。

#### REQ-SYNC-007 序号缺口处理（P0，All）

收到的事件 `seq` 不连续时，不能直接应用后续事件。

- 检测到 `seq > lastSeq + 1` 时，忽略该事件并触发 `since=lastSeq` 补拉。
- 补拉期间收到的事件先缓冲，补拉结束后按 `seq` 处理，已被补拉覆盖的事件自动忽略。
- 补拉完成后恢复正常事件应用。

**验收**

- Given 本地 `lastSeq=10`，When 收到 `seq=15` 的事件，Then 不直接应用，先补拉 11–15，再恢复。

#### REQ-SYNC-008 强制重同步（P0，All）

服务端返回 `resyncRequired=true` 时，客户端必须清空本地缓存并从可用起点重建。

- 触发条件：`since` 早于服务端 `syncFloor`，或 `since` 大于服务端当前最大序号。
- 客户端保留 outbox，清空本地 `clips` 与游标，用 `since=0` 或响应给出的起点全量拉取。
- 重同步完成后恢复 outbox 重放。
- 重同步期间 UI 展示「正在重新同步」。

**验收**

- Given 服务端因墓碑清理把 `syncFloor` 推进到 500，本地 `lastSeq=100`，When 同步，Then 返回 `resyncRequired=true`，客户端全量重建并保留待发操作。

#### REQ-SYNC-009 服务端保留与清理（P0，S）

服务端保留全部置顶记录 + 最近 500 条非置顶记录。

- 超出部分先软删除（写墓碑并推进 `serverSeq`），不直接物理删除。
- 墓碑保留 30 天，到期物理删除并推进 `syncFloor`。
- 清理任务在启动时与每 24 小时执行一次。
- 清理不删除置顶记录，即使超过 30 天。
- 分享链接持有内容快照，不受记录清理影响（见 REQ-SHARE-006）。

**验收**

- Given 服务端有 501 条非置顶记录，When 清理任务执行，Then 最旧的 1 条被软删除，其余保留。
- Given 墓碑已存在 31 天，When 清理任务执行，Then 墓碑被物理删除且 `syncFloor` 推进。

#### REQ-SYNC-010 幂等性（P0，S）

创建、置顶、删除接口必须支持安全重试。

- 创建：同 `id` 且内容相同返回 200 与原 `serverSeq`；同 `id` 但内容不同返回 409。
- 置顶：相同值不推进序号，返回当前状态。
- 删除：已删除返回当前状态，不再推进序号。

**验收**

- Given 同一 `id` 的创建请求被重复发送 3 次，When 服务端处理，Then 只存在 1 条记录，后两次返回 200 且不新增事件。

#### REQ-SYNC-011 多设备一致性（P0，All）

多设备同时操作时，最终状态一致。

- 记录内容不可变，不存在内容冲突。
- 置顶与删除为最后写入胜出（按服务端接收顺序）。
- 各端通过 `serverSeq` 感知最终状态。

**验收**

- Given 手机置顶 R、桌面同时删除 R，When 两个操作都到达服务端，Then 以服务端处理顺序为准，两端最终状态一致。

#### REQ-SYNC-012 同步状态展示（P0，All）

设置页展示同步状态，便于用户判断。

- 展示：正常 / 同步中 / 离线 / 同步失败 / 未配对。
- 展示最近一次成功同步时间。
- 提供「立即同步」按钮，手动触发一次补拉与 outbox 重放。

**验收**

- Given 网络断开，When 打开设置页，Then 状态显示「离线」并提供重试入口。
- Given 点击「立即同步」，When 同步完成，Then 最近同步时间更新。

#### REQ-SYNC-013 服务端重启恢复（P0，S）

服务端重启后数据与序号必须延续。

- 所有序号来自 SQLite 持久化的 `meta.server_seq`，不依赖内存。
- 重启后第一个写入的 `serverSeq` 必须大于重启前最大值。
- WebSocket 客户端重连后能继续用旧游标增量同步。

**验收**

- Given 重启前最大序号为 1000，When 重启后创建新记录，Then 新记录序号为 1001。

#### REQ-SYNC-014 服务端数据恢复后的客户端重建（P0，All）

服务端从备份恢复导致序号回退时，客户端必须能自愈。

- 客户端 `since` 大于服务端最大序号时，服务端返回 `resyncRequired=true`。
- 客户端清空本地缓存并全量重建，保留 outbox。
- 用户不需要手动清数据。

**验收**

- Given 服务端恢复到一周前备份，When 客户端携带较大 `since` 同步，Then 返回 `resyncRequired=true`，客户端自动重建。

#### REQ-SYNC-015 事件广播范围（P0，S）

所有已认证设备（含触发方）都收到变更事件。

- 广播内容包含 `id`、`serverSeq`、变更字段。
- 广播不包含完整文本以外的敏感信息；日志不记录文本。
- 单设备只允许一个活跃 WebSocket，新连接会关闭旧连接。

**验收**

- Given 设备 A 与 B 均在线，When A 创建记录，Then A 与 B 都收到 `clip.created`。
- Given 设备 A 建立第二个连接，When 新连接认证成功，Then 旧连接被关闭（4001）。

### 4.6 分享链接（SHARE）

#### REQ-SHARE-001 创建分享（P1，All）

已同步记录可生成一次性只读分享链接。

- 入口：历史列表操作菜单。
- 生成时客户端提交 `clipId`、`ttlSeconds`、`oneTime`。
- 服务端对记录内容做快照，分享页读取快照。
- 返回 `token`、`url`、`expiresAt`；客户端展示可复制的完整 URL。
- 待同步、失败、已删除记录不允许生成分享。

**验收**

- Given 记录 R 已同步，When 用户选择「24 小时分享」，Then 返回 `https://<host>/s/<token>` 与过期时间，复制成功提示「链接已复制」。

#### REQ-SHARE-002 有效期选项（P1，All）

提供固定选项，且限制合法区间。

| 选项     | `ttlSeconds` | `oneTime` |
| -------- | ------------ | --------- |
| 1 小时   | 3600         | false     |
| 24 小时  | 86400        | false     |
| 7 天     | 604800       | false     |
| 阅后即焚 | 86400        | true      |

- 默认选项为 24 小时。
- 服务端接受 60–604800 秒；超出范围返回 400。
- `oneTime=true` 时，首次成功打开即失效，即使未到 `expiresAt`。

**验收**

- Given 选择「阅后即焚」，When 生成链接并在浏览器打开一次，Then 页面展示内容；再次打开返回 410。

#### REQ-SHARE-003 只读分享页（P1，S）

`GET /s/{token}` 返回纯只读 HTML 页面。

- 不要求登录、不执行 JavaScript、不加载外部资源。
- 页面包含：正文与到期提示。
- 内容严格 HTML 转义，换行转为 `<br>` 或使用 `white-space: pre-wrap`。
- 响应头包含 CSP、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、`Cache-Control: no-store`。
- 支持移动端与桌面浏览器，自适应宽度，长文本可滚动。

**验收**

- Given 内容为 `<script>alert(1)</script>`，When 浏览器打开分享页，Then 原样显示该文本，不执行脚本。
- Given 内容包含 emoji 与多语言，When 打开，Then 正常显示，无乱码。

#### REQ-SHARE-004 链接无效与过期（P1，S）

不同失败原因返回不同状态码与页面文案。

| 情况             | HTTP | 页面文案                     |
| ---------------- | ---- | ---------------------------- |
| token 不存在     | 404  | 链接无效或已被删除           |
| 已过期           | 410  | 链接已过期                   |
| 一次性链接已打开 | 410  | 链接已被使用                 |

- 页面不泄露记录内容、记录 ID 或设备信息。
- 404 与 410 页面同样应用安全响应头。

**验收**

- Given 分享已过期，When 打开链接，Then 返回 410 与「链接已过期」。
- Given 一次性链接已打开过，When 再次打开，Then 返回 410 与「链接已被使用」。

#### REQ-SHARE-005 一次性消费的并发安全（P1，S）

一次性链接的消费必须原子化，不能出现两人同时打开都看到内容。

- 服务端在事务中检查 `opened_at IS NULL` 并写入打开时间。
- 只有一个请求能成功消费，其余返回 410。

**验收**

- Given 一次性链接未打开，When 两个请求同时发起，Then 只有一个返回 200 页面，另一个返回 410。

#### REQ-SHARE-006 分享内容快照独立（P1，S）

分享内容与记录解耦，记录删除或清理不影响已创建的分享。

- 创建分享时把内容复制到 `shares.content`。
- 记录被删除、软删除、物理清理后，分享在有效期内仍可访问。
- 分享不随记录置顶状态变化。
- 分享内容不在页面展示记录 ID。

**验收**

- Given 记录 R 已生成分享链接，When R 被删除，Then 分享链接在有效期内仍能打开并展示原文。
- Given R 被服务端保留策略清理，When 打开分享链接，Then 仍能正常展示。

#### REQ-SHARE-007 分享 Token 安全（P1，S）

分享 token 必须不可猜测。

- token 为 32 字节（256 bit）随机数，使用 base64url 无填充编码。
- 服务端只存 token 的 SHA-256 哈希，不存明文。
- 页面 URL 与访问日志不得记录完整 token；访问日志需脱敏。
- 不提供枚举接口，不提供分享列表接口。

**验收**

- Given 数据库被读取，When 查看 `shares` 表，Then 不存在可直接使用的明文 token。
- Given 查看服务端访问日志，When 包含分享页请求，Then token 已脱敏。

#### REQ-SHARE-008 分享限流（P1，S）

分享创建与访问都需限流，防止滥用与暴力枚举。

- 创建：120 次 / 分钟 / 设备（与设备接口共用配额）。
- 访问：60 次 / 分钟 / IP。
- 超限返回 429。

**验收**

- Given 同一 IP 1 分钟内访问分享页 61 次，When 第 62 次访问，Then 返回 429。

#### REQ-SHARE-009 分享入口的可用性约束（P1，All）

不可分享的状态必须明确禁用并说明原因。

- 待同步：提示「同步后可分享」。
- 失败：提示「请先处理失败记录」。
- 已删除：无分享入口。
- 离线：允许创建请求入队（与普通写入一致），或提示「网络恢复后可分享」；v1.0.0 采用「离线时禁用并提示」。

**验收**

- Given 设备离线，When 打开记录操作菜单，Then「生成分享链接」禁用并提示「网络恢复后可分享」。

#### REQ-SHARE-010 分享链接展示与复制（P1，All）

生成成功后展示链接与过期时间，支持复制与再次查看。

- 弹窗展示完整 URL、过期时间、是否一次性。
- 提供「复制链接」按钮，复制后提示。
- 关闭弹窗后不提供「查看已生成分享」列表（v1.0.0 不存储分享记录）。

**验收**

- Given 分享创建成功，When 点击复制，Then 剪贴板内容为完整 URL，提示「链接已复制」。

### 4.7 工具箱（TOOL）

#### REQ-TOOL-001 工具入口（P1，All）

工具箱页展示 5 个工具入口，网格布局。

| 工具         | 说明                         |
| ------------ | ---------------------------- |
| JSON 工具    | 格式化 / 压缩 / 校验         |
| Base64       | 标准与 URL-safe 编解码       |
| URL 编解码   | 组件编码与整串编码           |
| 时间戳转换   | 时间戳 ↔ 日期（本地 / UTC）  |
| 正则测试     | 匹配高亮与分组展示           |

- 所有工具完全本地运行，不联网、不上传、不写历史记录。
- 工具页面无需配对即可使用。

**验收**

- Given App 未配对，When 打开工具箱并使用 JSON 格式化，Then 功能正常，不提示配对。

#### REQ-TOOL-002 JSON 工具（P1，All）

支持格式化、压缩、校验三种操作。

- 输入上限 100 KiB，超限提示并禁用操作。
- 格式化：2 空格缩进，保留键顺序。
- 压缩：移除多余空白。
- 校验：合法时提示「JSON 合法」；非法时展示错误位置（行、列）与原因。
- 计算在后台线程执行，不阻塞 UI。

**验收**

- Given 输入合法 JSON，When 点击格式化，Then 输出缩进后的 JSON，键顺序不变。
- Given 输入缺少右括号，When 校验，Then 展示行号、列号与错误原因。

#### REQ-TOOL-003 Base64 工具（P1，All）

支持标准与 URL-safe 两种字母表的编解码。

- 提供「标准 / URL-safe」切换。
- 编码输入按 UTF-8 处理。
- 解码失败（非法字符、长度错误）时给出明确提示，不崩溃。
- 支持去除换行与空格的容错解码。

**验收**

- Given 输入 `你好`，When 标准编码，Then 输出对应 Base64；切换 URL-safe 后 `+` `/` 被替换为 `-` `_`。
- Given 输入非法 Base64，When 解码，Then 提示「不是合法的 Base64 内容」。

#### REQ-TOOL-004 URL 编解码（P1，All）

支持组件级与整串级编解码。

- 组件编码：对 `/`、`?`、`&`、`=` 等保留字符编码。
- 整串编码：保留 URL 结构字符。
- 解码支持 `%20` 与 `+` 两种空格形式（可选开关）。
- 非法百分号序列给出错误提示。

**验收**

- Given 输入 `a b&c=d`，When 组件编码，Then 输出 `a%20b%26c%3Dd`。
- Given 输入 `%E4%BD%A0%E5%A5%BD`，When 解码，Then 输出 `你好`。

#### REQ-TOOL-005 时间戳转换（P1，All）

支持秒 / 毫秒时间戳与日期互转。

- 自动识别 10 位（秒）与 13 位（毫秒）。
- 同时展示本地时区与 UTC 结果，包含 ISO 8601。
- 支持日期字符串转时间戳，格式错误时提示。
- 展示「当前时间戳」并支持一键填入。

**验收**

- Given 输入 `1730000000`，When 转换，Then 同时展示本地时间与 UTC 时间，二者相差与当前时区一致。
- Given 输入 `2026-13-01`，When 转换，Then 提示日期格式不合法。

#### REQ-TOOL-006 正则测试（P1，All）

支持正则匹配、高亮与分组展示。

- 输入上限 100 KiB，正则在 `Dispatchers.Default` 执行。
- 展示匹配次数、每处匹配的起止位置与分组内容。
- 支持常用标志：忽略大小写、多行、点匹配换行。
- 非法正则展示错误原因。
- 计算在后台线程执行；v1.0.0 不提供可靠的匹配超时，依靠 100 KiB 输入上限与后台执行降低灾难性回溯的影响。

**验收**

- Given 正则 `(\d+)-(\d+)` 与文本 `12-34`，When 执行，Then 展示 1 处匹配与 2 个分组。
- Given 灾难性回溯正则，When 执行，Then UI 保持可操作，用户可离开页面，不出现 ANR。

#### REQ-TOOL-007 结果操作（P1，All）

所有工具结果支持复制与清空。

- 「复制结果」写入系统剪贴板并提示。
- 「清空」同时清空输入与输出。
- 工具页不保存历史，退出即清空（进程存活期间可保留）。

**验收**

- Given JSON 格式化完成，When 点击复制结果，Then 剪贴板内容为格式化后的 JSON。

#### REQ-TOOL-008 离线与隐私（P1，All）

工具箱不依赖网络与配对状态。

- 断网、未配对、令牌失效时均可使用。
- 不写入历史记录、不上传内容、不记录输入输出日志。
- 不使用第三方统计 SDK 上报输入内容。

**验收**

- Given 飞行模式，When 使用全部 5 个工具，Then 功能均可用。
- Given 使用工具箱，When 查看历史记录，Then 不新增任何记录。

#### REQ-TOOL-009 输入规模限制（P1，All）

所有工具输入上限不超过 100 KiB；时间戳工具可限制为 32 字符。

- 超限时提示「输入超过 100 KiB」，禁用执行按钮。
- 限制在粘贴时即提示，不等到点击执行。

**验收**

- Given 粘贴 120 KiB 文本，When 进入 JSON 工具，Then 立即提示超限并禁用操作。

### 4.8 设置（SET）

#### REQ-SET-001 服务器地址（P0，All）

展示当前服务器地址，支持修改（需重新配对，见 REQ-PAIR-007）。

- 非 `localhost` 地址必须为 HTTPS，HTTP 仅允许 `localhost` / `127.0.0.1` 用于本地调试。

**验收**

#### REQ-SET-002 配对状态与设备信息（P0，All）

展示当前配对状态、设备名称、`deviceId` 摘要。

- 已配对：展示设备名称、服务器地址与配对状态。

#### REQ-SET-003 自动粘贴开关（P0，D）

控制是否把远端记录写入系统剪贴板，默认开启。

**验收**

- Given 默认状态，When 首次打开 Desktop 设置页，Then 自动粘贴开关为开启。

#### REQ-SET-004 自动发送开关（P0，D）

控制是否监听系统剪贴板并自动发送，默认关闭。

- 开启时提示「可能上传你复制的敏感内容」，需确认。
- 开关变更立即生效。
- Android 不展示该开关。

**验收**

- Given 首次开启自动发送，When 点击开关，Then 展示隐私提示，确认后才开启。

#### REQ-SET-005 主题（P0，All）

支持跟随系统、浅色、深色三种主题。

- 默认跟随系统。
- 选择立即生效并持久化。
- 重启后保持上次选择。

**验收**

- Given 系统为深色，When 选择「跟随系统」，Then App 使用深色主题。
- Given 选择「浅色」，When 重启 App，Then 仍为浅色。

#### REQ-SET-006 立即同步（P0，All）

手动触发一次补拉与 outbox 重放。

- 同步中按钮显示进度并禁用。
- 完成后提示结果（成功 / 失败原因）。
- 无网络时提示「当前离线」。

**验收**

- Given 存在 2 条待同步记录且网络正常，When 点击立即同步，Then 两条记录上传成功，状态更新。

#### REQ-SET-007 解除配对（P0，All）

见 REQ-PAIR-006。

#### REQ-SET-008 关于与版本（P0，All）

展示应用名、版本号、构建类型、开源许可（如有）与数据存储说明。

- 版本号来自构建配置，不在代码中硬编码多处。
- 提供服务器版本展示（`/healthz` 返回的 `version`，可选）。

**验收**

- Given 打开关于页，When 查看版本，Then 展示与构建产物一致的版本号。

#### REQ-SET-009 语言（P0，All）

v1.0.0 仅提供简体中文。

- 不展示语言切换入口。
- 所有用户可见文案为中文。
- 代码中的错误码映射为中文提示。

**验收**

- Given 使用任意页面，When 触发错误，Then 提示为中文，不直接展示英文错误码。

#### REQ-SET-010 Desktop 窗口行为（P0，D）

窗口尺寸与最小尺寸符合桌面使用习惯。

- 默认 1000×700，最小 640×480。
- 记住上次窗口大小与位置（可选，若实现需保证多显示器安全）。
- 关闭窗口退出应用（v1.0.0 无托盘常驻）。

**验收**

- Given 首次启动 Desktop，When 打开窗口，Then 尺寸为 1000×700。
- Given 缩放到最小尺寸，When 继续缩小，Then 窗口不再变小。

### 4.9 平台与运行环境（PLAT）

#### REQ-PLAT-001 Android 系统版本（P0，A）

最低支持 Android 8.0（API 26）。

- 目标 SDK 使用当前稳定版本。
- 在 API 26 设备上核心功能可用。

**验收**

- Given API 26 设备，When 安装并完成配对，Then 发送、接收、复制、历史功能正常。

#### REQ-PLAT-002 Android 无后台剪贴板能力（P0，A）

不申请后台读取剪贴板的权限，不实现后台常驻。

- 不声明 `FOREGROUND_SERVICE` 相关能力（v1.0.0）。
- 不发送通知。
- 不引导用户加入电池白名单。

**验收**

- Given App 退到后台，When 桌面发送文本，Then 手机不写剪贴板、不弹通知。

#### REQ-PLAT-003 Android 分享入口声明（P0，A）

Manifest 正确声明 `ACTION_SEND` 与 `ACTION_PROCESS_TEXT`。

- `ShareReceiverActivity` 设置 `exported=true`。
- 仅接受 `text/plain`。
- 对空文本、超长文本、异常 Intent 做防御处理，不崩溃。

**验收**

- Given 从其他应用分享 `text/plain`，When 选择 Clipbox，Then 正常打开发送页。
- Given 分享 Intent 缺失 `EXTRA_TEXT`，When 打开，Then 展示空状态，不崩溃。

#### REQ-PLAT-004 Desktop 剪贴板实现（P0，D）

使用 AWT 系统剪贴板读写。

- 轮询间隔 500ms，内容哈希比对去重。
- 兼容 Windows / macOS / Linux。
- Linux Wayland 下 `FlavorListener` 不可靠时，以轮询为准。

**验收**

- Given macOS 与 Windows，When 复制文本，Then 自动发送（若开启）在 2 秒内触发。

#### REQ-PLAT-005 桌面操作系统支持（P0，D）

支持 Windows 10+、macOS 12+、主流 Linux 桌面。

- 提供对应平台的安装包或可执行分发方式。
- 不要求用户预装 JDK。

**验收**

- Given 干净的 Windows 机器，When 安装并启动，Then 可完成配对并收发文本。

#### REQ-PLAT-006 服务端部署（P0，S）

提供 Docker Compose + Caddy 一键部署。

- 服务端单 JAR、单容器，数据落盘到挂载卷。
- Caddy 自动签发并续期 HTTPS 证书。
- 容器以非 root 运行，根文件系统只读，`/tmp` 使用 tmpfs。
- 配置通过环境变量注入，敏感项不写入镜像。

**验收**

- Given 一台 2 核 2GB 服务器，When 执行 `docker compose up -d`，Then 服务在 HTTPS 下可用，`/healthz` 返回 200。

#### REQ-PLAT-007 服务端配置校验（P0，S）

启动时校验必需配置，缺失或非法时快速失败并打印明确原因。

- `ADMIN_TOKEN` 必填且长度 ≥32。
- `PUBLIC_BASE_URL` 必填且必须为 HTTPS。
- 端口、数据目录、各项上限需为合法值。
- 启动日志不打印令牌明文。

**验收**

- Given 未设置 `ADMIN_TOKEN`，When 启动容器，Then 启动失败并打印「ADMIN_TOKEN 未配置」。
- Given `PUBLIC_BASE_URL=http://...`，When 启动，Then 启动失败并提示必须使用 HTTPS。

### 4.10 非功能需求（NFR）

#### REQ-NFR-001 传输安全（P0，All）

所有业务流量走 HTTPS / WSS。

- 服务端不监听明文业务端口对外提供服务。
- 客户端拒绝非 `localhost` 的 HTTP 地址。
- 启用 HSTS。

**验收**

- Given 使用 `http://` 访问正式域名，When 请求业务接口，Then 被拒绝或重定向到 HTTPS。

#### REQ-NFR-002 设备令牌安全（P0，All）

- 令牌为 32 字节随机数，仅配对成功时返回一次。
- 服务端只存 SHA-256 哈希。
- 客户端令牌存于应用沙箱内的 DataStore；v1.0.0 不引入 Keystore / 钥匙串封装，风险与加固计划在架构文档中说明。
- 令牌不出现在日志、崩溃上报、URL 中。

**验收**

- Given 查看服务端数据库，When 检查 `devices` 表，Then 无明文令牌。
- Given 查看客户端日志，When 搜索令牌，Then 无结果。

#### REQ-NFR-003 配对安全（P0，S）

- 配对码 6 位数字、10 分钟有效、一次性。
- 配对请求限速 5 次 / 分钟 / IP（含成功与失败）。
- 配对码以明文存于数据库（短时效），过期后清理。
- 仅启动时自动生成的配对码允许打印一次（便于自助配对），管理接口生成的码与设备令牌不打印。

**验收**

- Given 配对码已使用，When 再次使用，Then 返回 400 且不签发新令牌。

#### REQ-NFR-004 分享页安全（P0，S）

- 严格 HTML 转义，禁止脚本执行。
- CSP：`default-src 'none'; style-src 'unsafe-inline'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`。
- 响应头包含 `X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、`Cache-Control: no-store`。
- 不加载外部字体、图片、脚本。

**验收**

- Given 内容包含 `<img src=x onerror=alert(1)>`，When 打开分享页，Then 原样显示文本，无请求发出、无脚本执行。

#### REQ-NFR-005 管理接口安全（P0，S）

- 仅 `X-Admin-Token` 可访问。
- 令牌比较使用恒定时间比较。
- 限流 10 次 / 分钟 / IP。
- 可选在 Caddy 层限制来源 IP。
- 管理接口不返回设备令牌或记录内容。

**验收**

- Given 无 `X-Admin-Token`，When 调用管理接口，Then 返回 401。

#### REQ-NFR-006 隐私与日志（P0，All）

- 服务端日志不记录文本内容、设备令牌、分享 token 明文。
- 客户端崩溃日志不包含记录内容。
- 不集成第三方行为分析 SDK。
- 数据在服务端明文存储，需在文档与设置页「关于」中明确说明。

**验收**

- Given 正常使用一天，When 检查服务端日志，Then 无记录内容与令牌。

#### REQ-NFR-007 手机到桌面时延（P0，All）

已配对且双端在线时，手机发送到桌面剪贴板可用的端到端时间 ≤5 秒（P95）。

- 测试条件：单条文本 ≤4 KiB，正常网络。
- 计时起点：手机点击发送；终点：桌面剪贴板可粘贴出新内容。

**验收**

- Given 双端在线，When 连续发送 20 条，Then 至少 19 条在 5 秒内到达。

#### REQ-NFR-008 桌面到手机可见时延（P0，All）

桌面发送后，手机打开 App 到记录可见 ≤3 秒（P95）。

- 计时起点：手机回到前台；终点：列表展示该记录。

**验收**

- Given 桌面已发送 3 条，When 手机回到前台，Then 3 秒内列表展示这 3 条。

#### REQ-NFR-009 搜索响应（P0，All）

本地搜索 300ms 防抖后，结果展示 ≤100ms（200 条记录规模）。

**验收**

- Given 本地 200 条记录，When 输入关键词，Then 防抖结束后 100ms 内展示结果。

#### REQ-NFR-010 离线可靠性（P0，All）

- 离线状态下所有本地功能可用。
- outbox 不丢操作，重启后继续重放。
- 恢复网络后自动同步，不需要用户手动操作。

**验收**

- Given 离线操作 10 次（发送 / 置顶 / 删除），When 恢复网络，Then 10 次操作全部同步且无重复。

#### REQ-NFR-011 WebSocket 可靠性（P0，All）

- 断线自动重连，无限重试（4401 令牌失效与 4001 连接被替换除外）。
- 重连后通过游标补拉，消息不丢不重。
- 单设备仅一个活跃连接。

**验收**

- Given 网络抖动 10 次，When 恢复，Then 数据最终一致，无重复记录。

#### REQ-NFR-012 数据持久化（P0，All）

- 服务端重启数据完整。
- 客户端重启历史完整（在本地保留范围内）。
- 数据库损坏时可检测并提示，不静默丢数据。

**验收**

- Given 服务端重启 3 次，When 检查数据，Then 记录数与序号连续。

#### REQ-NFR-013 备份（P0，S）

- 每日自动备份 SQLite，保留 7 天。
- 备份文件权限 600。
- 提供恢复步骤文档。

**验收**

- Given 备份任务运行 8 天，When 查看备份目录，Then 保留最近 7 份。

#### REQ-NFR-014 兼容性（P0，All）

- Android 8.0–最新稳定版。
- Desktop Windows 10+ / macOS 12+ / 主流 Linux。
- 服务端 JDK 21 运行。

**验收**

- Given 各平台矩阵设备，When 执行核心流程，Then 均通过。

#### REQ-NFR-015 资源占用（P0，S）

- 服务端常驻内存 <400MB（`-Xmx256m`）。
- SQLite 数据文件在 500 条规模下 <10MB。
- 日常同步带宽占用可忽略（100 条 / 天约 0.5MB）。

**验收**

- Given 稳定运行 24 小时，When 查看容器内存，Then 常驻内存 <400MB。

#### REQ-NFR-016 可维护性（P0，All）

- 关键同步逻辑有单元测试。
- 服务端接口有集成测试。
- 数据库迁移使用版本化脚本，可重复执行。
- 构建使用 Gradle Version Catalog 锁定版本。

**验收**

- Given 执行 `./gradlew test`，When 测试完成，Then 核心模块测试通过。

#### REQ-NFR-017 可访问性（P0，All）

- 所有可点击元素有内容描述，支持 TalkBack / 屏幕阅读器。
- 文本对比度符合 WCAG AA。
- 支持系统字体缩放，不出现文字截断导致的不可用。
- 键盘可完成 Desktop 核心操作（输入、发送、列表导航）。

**验收**

- Given 开启 TalkBack，When 浏览历史列表，Then 能读出内容、来源、时间与操作按钮。

以下为 v1.0.0 发布前必须通过的端到端场景。

## 8. 与交接文档 v0.1 的差异

| 差异项             | 交接文档 v0.1                       | 本文档 v1.0.0                                                   | 原因 |
| ------------------ | ----------------------------------- | --------------------------------------------------------------- | ---- |
| 版本号             | 未定义                              | v1.0.0                                                          | 建立可验收基线 |
| 同步游标           | `after` 使用 ULID                   | 服务端 `serverSeq` + `since`，ULID 仅作主键与展示排序           | ULID 无法覆盖旧记录置顶 / 删除，见 ADR-0001 |
| 分享链接内容       | 引用 `clip_id`                      | 创建时内容快照，记录删除不影响分享                              | 避免分享随记录消失，见 ADR-0002 |
| 分享有效期         | 默认 24h，支持阅后即焚              | 明确 4 个选项与 60–604800s 合法区间                            | 消除歧义 |
| 分享撤销           | 未提及                              | v1.0.0 不提供                                                   | 控制范围 |
| 服务端保留         | 500 条，置顶不参与清理              | 保留全部置顶 + 最近 500 条非置顶；超额软删，墓碑 30 天          | 明确清理与同步语义 |
| 客户端保留         | 200 条                              | 200 条非置顶 + 全部置顶；本地清理不上传                         | 避免本地清理误删服务端数据 |
| 请求体上限         | 128KB                               | 512 KiB                                                         | JSON 转义可膨胀约 6 倍，128KB 会误拒合法 64 KiB 文本 |
| 正文超限状态码     | 413                                 | 400 `VALIDATION_ERROR`；请求体超限仍为 413                      | 区分字段大小校验与整个请求体上限 |
| 配对码自助         | 启动时自动生成并打印                | 保留，并明确日志只打印配对码不打印令牌                          | 安全边界 |
