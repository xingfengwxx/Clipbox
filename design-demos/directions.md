# Clipbox 三端设计 · 六张方向卡

## 共同 spec

- **项目**：Clipbox v1.0.0，离线优先的跨设备文本中转与本地工具箱。
- **受众**：单一自用者，技术背景，手机 + 电脑多设备；在意隐私、离线可用、不啰嗦。
- **场景**：在手机上复制一段文本，几秒内在电脑上粘贴；或反过来。也会在电脑前整理历史、生成只读分享链接、用本地工具处理 JSON / Base64 / URL / 时间戳 / 正则。
- **情感基调**：安静、克制、精确；像一件用久了不累的工具，不像一个催促用户的产品。
- **输出格式**：Android 412×915；Desktop 1000×700；分享页正文最大宽度约 680px；三端同一套设计语言。
- **已知约束**：内容全是文本，没有图片；需覆盖浅色 / 深色、简体 / 繁體 / English；正文 ≥14px、标签 ≥12px、对比度 ≥4.5:1；触控目标 ≥48dp；不做动态取色。
- **内容**：真实剪贴样本（中文会议纪要、英文段落、JSON、URL、SSH 命令、emoji），真实设备名与相对时间；不用 Lorem，不编造数据。

## 方向卡

### C1 · 仪器清单（最佳设计师 A：Dieter Rams / Braun）

- **逻辑与来源**：Dieter Rams 在 Braun 形成的「少而精确」工具观：严格网格、中性灰白、单一信号色、读数式信息、没有装饰。不是模仿某件 Braun 产品，而是用他的思维处理一个文本工具。
- **借的是什么**：网格与基線严格对齐；底色为暖灰白，文字近黑；橙色只给「当前 / 主操作 / 需要看一眼的状态」；元数据用等宽字体像仪器读数；发丝分隔线替代卡片；按钮与输入框有明确的边界，不靠阴影。
- **主角素材**：文本本身 + 发送框下方的 UTF-8 字节读数。字节数像仪器的刻度，是这个产品真实存在的细节。
- **骨架**：顶部一条状态读数带（同步状态 / 设备 / 时间），中间是发送器，下面是一列严格对齐的记录；底部三个文字标签导航。展示板用测量刻度与基线网格做构图。
- **胆量花在哪**：发送器做成一块「仪器面板」——输入区、字节读数、发送键在同一块面板上，读数和输入同宽对齐；其余全部安静。
- **form 来自内容的哪里**：文本传输本质上是一次「计量」——多少字节、从哪台设备、什么时候、是否同步；把计量做成界面的骨架，而不是装饰。

### C2 · 网格索引（最佳设计师 B：Experimental Jetset）

- **逻辑与来源**：Experimental Jetset（阿姆斯特丹，1997–），以 Helvetica、严格网格、概念性重复与「文字即图像」著称；作品常以白、黑与一个红/蓝构成。用他们的思维做一份「剪贴索引」，不做海报。
- **借的是什么**：四栏严格网格；一种无衬线、三档字号；一个红色强调；横向与纵向的极细网格线；时间与来源作为结构列；没有图标；发送器是一条全宽行，不是卡片。
- **主角素材**：文本，以及它的索引信息（时间、来源、状态、字节）。
- **骨架**：表格式列表——左列时间、第二列来源、第三列内容、右列状态/字节；顶部大字标题 + 红色横线；底部文字导航。展示板用红色基线、网格与版面标注做构图。
- **胆量花在哪**：把历史做成一张「索引表」，四列严格对齐到像素；红色只给置顶与当前 tab，其余全是黑与白。
- **form 来自内容的哪里**：剪贴记录本来就是带时间、来源、状态的记录；索引表是最诚实的形式，不需要卡片或装饰。

> 备选说明：C2 最初是原研哉「空白与纸」，缩略图阶段发现留白过头、第一眼像页面没渲染完，按规则换来源重画为网格索引。原方向不再进入完整版。

### C3 · 原生清单（现实参照 A：Things 3）

- **逻辑与来源**：Things 3（Cultured Code，<https://culturedcode.com/things/>），2026-11-13 亲眼截图 `refs/ref-things3-ui.png`。核实存在，官网称其界面「像一张干净挺括的纸」。
- **借的是什么**：纯白表面、近黑文字、一个蓝色强调；大标题 32px 紧字距；行高慷慨；从复选框右侧起笔的发丝分隔线；圆角方形控件；底部导航 + 悬浮主操作；弹层用大阴影浮起，而不是满屏抽屉。
- **主角素材**：干净的列表行；每行一条文本、一行极小的元数据。
- **骨架**：原生列表 + 顶部发送器；置顶区用一个小标题分组；操作通过行尾更多按钮进入底部面板。
- **胆量花在哪**：列表的节奏本身——行高、缩进、发丝线的起笔位置全部对齐到同一条基线；没有一处多余的颜色。
- **form 来自内容的哪里**：剪贴记录天然是一条一条的，像待办清单；用户来这里是「取一条」，不是「逛内容」。

### C4 · 剪贴卡片架（现实参照 B：Paste）

- **逻辑与来源**：Paste（<https://pasteapp.io/>），2026-11-13 亲眼截图 `refs/ref-paste-hero.png`。核实存在，产品覆盖 Mac / iPhone / iPad，核心视觉是彩色卡片架。
- **借的是什么**：把每条剪贴做成一张「卡片」，用类型标签（TEXT / LINK / JSON / CODE）区分；卡片按时间进入一个可扫视的架子；卡片可以轻微错位、叠放，像从桌上拿起一张纸条；设备来源用一个小徽标贴在卡片角上。颜色降饱和，只保留纸张色差。
- **主角素材**：每条文本作为一张可被「拿起」的卡片；卡片本身就是内容。
- **骨架**：两列卡片架（手机）/ 横向卡片架（桌面）；置顶卡片在第一排并略微抬起；发送器是一张空白卡片，固定在架子顶部。
- **胆量花在哪**：卡片架不是等距网格——置顶卡片抬起、最近一条略大、其余像被翻过一样错落；但文字始终左对齐、可读。
- **form 来自内容的哪里**：剪贴记录是「一张一张的纸条」，不是文档；卡片架让「找一条、拿走」这个动作成立。

### C5 · 硬件面板（秒数轮盘 · App 分区 01：Teenage Engineering / OP-1）

- **逻辑与来源**：秒数 36 → `36 % 12 + 1 = 1`，App 分区第 1 号「硬件面板 Hardware Panel」；样张 `assets/style-specimens/app/01-hardware-panel.jpg`。参考 Teenage Engineering OP-1 / EP-133 的界面语言。
- **借的是什么**：近黑屏幕、信号橙只给当前激活、点阵 / 等宽读数、严格方格网格、丝印式小标签、按键的「压下去」厚度（inset 底边阴影）；一屏只有一种强调色。
- **主角素材**：读数与按键。UTF-8 字节数、同步状态、设备名都做成仪器读数；工具箱 5 个入口做成 5 个方形键。
- **骨架**：顶部读数带；中间发送器像一条命令行（块状光标）；下面记录像日志行；底部工具箱键阵。展示板用细网格与丝印标注。
- **胆量花在哪**：发送器做成命令行，块状光标停在输入末尾；字节读数用点阵字；其余区域保持极暗、极静。
- **form 来自内容的哪里**：这是一个技术用户每天用的文本工具，像一台口袋仪器；字节数与同步状态就是它的仪表。
- **风险**：容易用力过头。这是六个候选里唯一允许「bold」的一张；去掉这套仪表语言，信息是否更清楚？如果是，就不选它。

### C6 · 版心与朱砂（秒数轮盘 · East 分区 01：吕敬人书籍设计）

- **逻辑与来源**：秒数 36 → `36 % 12 + 1 = 1`，East 分区第 1 号「吕敬人书籍设计」；样张 `assets/style-specimens/east/01-lu-jingren.jpg`（总览 `sheet-east.jpg` 第 1 格）。
- **借的是什么**：暖纸底 + 深墨黑正文；朱砂红只出现一处；天头大、地脚也大；切口一侧留一条窄旁注栏；内容用衬线；标签极小；行距宽松；不用卡片，用版心与留白分区。
- **主角素材**：被排成一页的文本；旁注栏里的设备、时间、字节数。
- **骨架**：像一页书——上方大字标题，左侧窄旁注，右侧正文；置顶项旁注处盖一枚朱砂小印；底部导航像书眉。
- **胆量花在哪**：把元数据全部挪到左侧窄栏，形成真正的旁注系统；正文区因此非常干净。朱砂只给置顶，不给按钮。
- **form 来自内容的哪里**：剪贴记录是一段段可读的文本；把设备与时间放进旁注，让正文回到阅读。
- **风险**：暖纸 + 衬线是 2026 年 AI 页面的常见外观家族；只有旁注结构和「朱砂只一处」能证明它不是默认皮肤。若三版都落在这一家族，弃用。
